# Poulygon native 3D

No unit tests, synthetic probes, mocks, fabricated inputs or simulated devices.
Validate by compilation and the actual application on the VAIO P. The rotating
cube is an application scene, not a test harness. Do not run inherited
Poulsback test programs or add a software renderer to substitute for hardware.

Use Depot for the i386 build and Nix for host tools. Keep the target OS packages
and existing terminal sessions intact. Run on a free Linux VT and preserve a
working recovery console. Never retry, reset or unload after an unknown GPU
outcome.

Keep the pinned upstream libraries unchanged and preserve their notices. Use
DoubleDensity <doubledense@gmail.com> for commits. No DCO certification by agents.
The application has no network code yet. Keep simulation independent of rendering;
add a real transport only with an actual multiplayer feature.

## Public project writing

Keep public repository documentation, comments, CLI messages, commit messages
and PR prose focused on the project and its users. Do not include personal or
family names, relationships, private hostnames, deployment state, or conversation
handover language. Hardware model details may stay where they define the target
platform or substantiate testing. Preserve required licensing, attribution and
upstream contribution disclosures. Before publishing previously local work,
check both its current files and the history that will become reachable.
